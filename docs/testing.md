# Тестирование

В проекте используются два уровня тестов: модульные (unit) и сквозные (e2e).

## Модульные тесты (Jest + JSDOM)

Модульные тесты проверяют изолированную работу класса `Popover`: создание экземпляра, показ/скрытие попапа, правильность расчёта позиции.

**Запуск:**

```bash
    npm test
```

Тесты выполняются в среде JSDOM, не требуя браузера. Покрытие кода можно проверить командой:

```bash
    npm run coverage
```

Требуемый порог покрытия – не менее 90%.

## E2E-тесты (Puppeteer)

E2E-тесты проверяют работу виджета в реальном браузере: клик по кнопке, появление попапа с правильным текстом, переключение между попапами, закрытие по клику вне.

**Запуск:**

```bash
    npm run test:e2e
```

**Важно:** E2E-тесты требуют предварительно собранного проекта и запущенного сервера. Команда `test:e2e` автоматически выполняет сборку (`npm run build`), запускает статический сервер (`http-server`) и затем тесты.

### Особенности на Windows

На некоторых версиях Windows могут возникать конфликты из-за незавершённых процессов Chrome, блокирующих временные папки. В этом случае тесты могут падать с ошибкой `The browser is already running`. Если локально они не проходят, но на GitHub Actions (CI) успешны – это допустимо. Рекомендуется:

- Завершить все процессы Chrome перед запуском (вручную или добавив `taskkill` в тесты).
- Перезагрузить компьютер.
- Основной упор делать на прохождение тестов в CI.

## CI/CD

GitHub Actions настроен на автоматический запуск тестов при каждом пуше. В workflow выполняются:

- `test` – модульные тесты,
- `e2e` – сквозные тесты,
- `build-and-deploy` – сборка и публикация на GitHub Pages (только если тесты прошли).

Статус последнего билда отображается в бейдже в README.
